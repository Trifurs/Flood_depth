# Hydro-v12 像元优先与无事件依赖优化报告

## 结论

Hydro-v12 是当前默认模型。训练时不读取事件 ID 计算深度、不确定性、
nnPU 或物理损失；验证集以全部有效正水深像元的 micro MAE 选择
`best.pth`。推理输入不含事件标识，同一栅格不会因评价时填写的
`source_event_id` 不同而改变预测。

完整 validation 结果为：

| 像元指标 | 历史层级选模检查点 | Hydro-v12 | 变化 |
|---|---:|---:|---:|
| MAE (m) | 0.525401 | **0.522351** | **-0.58%** |
| RMSE (m) | 0.799495 | **0.792464** | **-0.88%** |
| P90 绝对误差 (m) | 1.299958 | **1.193673** | **-8.18%** |
| `|error| <= 0.25 m` | 0.418362 | **0.422432** | +0.004070 |
| `|error| <= 0.50 m` | **0.640523** | 0.639580 | -0.000943 |
| `|error| <= 1.00 m` | 0.839655 | **0.844708** | +0.005053 |

改善幅度较小，且 0.50 m 命中率轻微下降，因此不将其表述为全指标
显著改进。它是与实际部署评价口径对齐的工程候选。

## 为什么不再按事件优化

数据审计显示 train 有 105 个栅格和 105 个唯一 `source_event_id`，没有重复事件。
因此历史的“事件内水深分层、再平均事件”在这个子集上数学上等价于
“每个栅格内水深分层、再平均栅格”。Hydro-v12 将实现显式改为
`sample_depth_bin`，并用单元测试验证替换事件 ID 不会改变损失。

这也意味着 Hydro-v12 的主要收益不是新的事件建模能力。其训练轨迹与历史
分层目标一致，改善来自把检查点选择从事件/分层指标改成部署所关心的
像元 MAE。历史检查点加载后 MAE 为 0.525401；Hydro-v12 保存零起始
epoch 33 的 0.522350。

## 候选比较

所有新候选只用 train/validation，且按 validation 像元 MAE 排名。

| 候选 | 损失/归约 | val 像元 MAE | val RMSE | 决定 |
|---|---|---:|---:|---|
| 纯像元 L1 (v10) | 所有正像元直接 micro | 0.606394 | 0.913489 | 拒绝；被浅水像元数量主导 |
| 全局水深层 (v11) | 全 batch 水深层等权 | 0.525832 | 0.797179 | 接近但未超越基线 |
| **逐栅格水深层 (v12)** | **栅格内分层，再平均栅格** | **0.522351** | **0.792464** | **当前默认** |

纯 L1 的失败说明，“像元指标为主”不等于“训练损失必须是未分层的
像元 L1”。训练仍需用 train-only 水深层防止罕见深水样本被浅水数量淹没；
但检查点选择必须与部署像元误差一致。

## 物理约束边界

当前仅保留权重 0.02 的局部 WSE Laplacian，作为弱平滑先验而非物理方程。
洪水深度文献支持使用 DEM/粗糙度与物理引导信息，但也指出 PINN 的事件特定
限制：[HESS 综述](https://hess.copernicus.org/articles/26/4345/2022/)。实际洪水框架中从
DEM 和范围恢复水面高程也支持“局部水面约束”这一弱先验：
[HESS 运行框架](https://hess.copernicus.org/articles/26/4013/2022/)。

本数据是异步事件合成影像，没有速度、流量、时序降雨与边界条件，所以质量
守恒或浅水方程残差不可识别。已发表的 SWE PINN 工作同样报告损失平衡、复杂
地形和过强质量守恒权重带来的训练问题：
[WRR 2025](https://agupubs.onlinelibrary.wiley.com/doi/full/10.1029/2025WR040052)。因此没有把
不可观测的完整水动力残差强加到模型中。

## test 使用边界

早期 Hydro-v6/Hydro-v9 冻结比较已经暴露过当前 test。Hydro-v12 没有在 test 上运行，
本轮也没有使用 test 选模、调损失或调物理权重。由于开发者已知道历史 test
表现，严格的最终泛化结论应使用新的、未触碰的外部数据，而不是再次检查
当前 test。
